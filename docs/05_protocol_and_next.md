# 05 · 评估协议与下一步

## 少样本到底少在哪里

- **参考样本**：推理时提供少量已标框实例，不更新模型参数。
- **微调样本**：用于反向传播，更新参数。
- 两者都可叫 few-shot，必须分别记录；shot 按“每类实例数”还是“图像数”也须写清。
- 训练集和验证集不必等量。训练每类 5 个实例，验证每类几十个很正常。
- 参考/训练/验证/测试按视频段、工位或时间段分开，防止相邻帧泄漏。固定验证/测试集，仅变化训练与参考样本。

300 张历史集合保留为历史验证基准；如果它已被反复用于选模型/阈值，就不能又称全新独立测试集。

## 指标分两层

| 用途 | 指标 | 解释 |
|---|---|---|
| 检出能力 | AP50、AP50:95 | 全部保存候选按分数排序；多类宏平均 |
| 边界精度 | AP85/90/95 | 高 IoU 下的完整 AP，不先删误检 |
| 自动接收 | 固定阈值 P/R、每百图 FP、框合格率/GT 覆盖率 | 同时报告接收量；不能只报“100% 精度的 3 个框” |
| 自定义框质量 | 四项≤20% | 宽、高、横纵中心误差同时受限 |

四项误差分别以 GT 宽/高归一化：

`ew=|wp-wg|/wg, eh=|hp-hg|/hg, ex=|cxp-cxg|/wg, ey=|cyp-cyg|/hg`。

**框质量容差以 GT 为参照；修框动作上限以原预测框为参照。** 二者分母不同，不能混称“20%”。

同类、一对一匹配；重复框算 FP，漏检留在 GT 分母。四项≤20%匹配使用独立联合条件，不先要求 IoU≥0.85。历史报告的几何 AP 与标准 IoU AP分别保存。

MLLM 若无可信的框分数，主要报固定输出集合的 P/R、覆盖和框质量；若给全部框同分，AP 的排序缺乏区分力，还会受并列分数处理影响。不要把自报“信心”自动当成已校准置信度。

## 先补一组可回答问题的消融

| 编号 | 设置 | 要回答的问题 |
|---|---|---|
| A | 原始 YOLOE + 固定参考 | 基准效果和参考波动多大 |
| B | 仅训练 SAVPE | 只改善提示表示是否足够 |
| C | 保留 SAVPE，解冻少量后层/检测头 | 领域与定位适配是否有收益 |
| D | 删除 SAVPE，固定类别微调 | 固定目标自动标注的可用上限 |

A/B/C 属于动态提示协议，D 单独列为固定类别适配。相同样本预算、训练图像、增强、停止规则；至少 3 个抽样种子，报告均值与范围。C 的具体可训练层需列出，不能只写“backbone 微调”。

先用固定 5-shot 跑通以上设置；保存所有预测坐标、分数、类别、图像 ID。误差分为：类别错、背景误检、重复框、正确类别但定位不足、漏检。只有定位错误占主导时，再优先试受限修框；若语义误检多，先试候选审核。

## 每次运行必须留什么

`run.json`：数据指纹、划分/参考 ID、类名映射、模型与权重哈希、上游 commit、seed、Trainer、训练参数名、prompt 完整快照、坐标约定、分数来源、推理阈值/NMS/maxDets、完成/失败图数、耗时。

`predictions.json`：逐图原始候选，不要只留汇总 AP。GT 清单独立保留。

选择阈值在验证集上完成；测试集仅评估一次。当前最需要的是把 B/C/D 的能力差别说清，再决定扩展 MLLM 两步方案。
